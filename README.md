# 로켓견적 — 타일·벽돌 매장 도우미

## 1. 문제
견적 계산 · 재고 확인 · 샘플 추적을 단가표 · 엑셀 · 전화로 따로 한다.
견적 한 건에 5–10분이 걸리고 계산 실수가 나며, 재고 부족은 늦게 알고, 샘플이 어디 있는지 바로 모른다.

## 2. 누가 · 언제
벽돌 · 타일 매장 직원과 영업 담당이 전화 견적, 매장 상담, 재고 확인, 샘플 문의 때 연다.

> 시공업자: "적벽돌 1층 건물 30평짜리면 몇 장이에요?"
> → 벽돌 · 적벽돌 · 190×57 · 30평 1층 입력 → **7,560장 = 5파렛트 + 1,060장**이 바로 뜬다.
> → 재고 화면에서 그 벽돌이 초록(충분)인지 본다.

## 3. 화면 3개
| 주소 | 화면 | 하는 일 |
| --- | --- | --- |
| `/` | 로켓 견적 | 벽돌/타일 → 제품명 → 사이즈 → 면적(㎡ 또는 건물 평수 · 층수) · 로스율 → 필요 장수 · 파렛트 수. 견적서 인쇄(A4 · PDF 저장) |
| `/stock` | 재고 신호등 | 빨강 개수를 크게, 빨강이 위로. 전체/벽돌/타일 필터. 보기 전용 |
| `/samples` | 샘플은 지금 어디에? | 발송 준비 → 발송 → 도착 → 확인완료 4칸 보드. 다음 단계 단추, 메모(발송 준비) · 피드백(확인완료), 7일 넘게 도착 안 된 카드는 노란 테두리 |

계산 규칙: ㎡당 장수 = 올림(1,000,000 / ((길이+12) × (높이+12))), 필요 장수 = 올림(면적 × ㎡당 장수 × (1 + 로스율)), 건물 30평 1층 ≈ 외벽 100㎡. 자세한 내용은 [spec/calc-rules.md](spec/calc-rules.md).

## 4. 데이터 · 규칙
- 로그인 없음 · DB 없음 · 앱 안 AI 없음 · API 키 없음
- 규격 · 파렛트당 장수는 업계 표 기준, 재고 · 샘플 · 거래처는 전부 가상(○○건설 같은 이름, 연락처 없음)
- 단가는 자주 바뀌므로 넣지 않는다 — 장수 계산 전용
- 샘플 단계 · 메모 · 피드백은 이 브라우저(localStorage)에만 저장
- 데이터 모양은 [spec/data-model.md](spec/data-model.md), 데이터는 `npm run gen:data`로 다시 만든다

```bash
npm install
npm run dev      # http://localhost:3000
npm test         # 계산 규칙 테스트
npm run build
```
